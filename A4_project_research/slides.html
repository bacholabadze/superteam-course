Problem & users

  • Problem: liquidity is split across dozens of DEXs; best price needs routing and order splitting.
  • Users: traders on jup.ag, plus wallets and apps via API (its Price API is used by most Solana wallets).
  • Why Solana: multi-hop routes need many accounts in one atomic tx; cheap fees, ~400 ms blocks and lookup tables make that practical.
  • Competitors: OKX DEX aggregator, DFlow, Titan; Drift (perps); trading bots.

How it works · risks · improvements

Real on-chain programs, run by off-chain keepers

DCA keeper FlashFill → JUP6 route → Fulfill

Perps keeper pushes signed prices → refresh JLP value

Off-chain

  • Metis routing engine + RFQ market makers
  • Keepers that fill DCA, limit and perps requests
  • Swap / Price / Tokens APIs with API keys
  • Tx landing: high-stake validator, MEV protection

Risks → improvements

  • Upgradeable programs: publish the multisig and timelock setup
  • Keeper dependence: permissionless fills
  • Oracle risk for perps and JLP holders
  • One API for the ecosystem: an outage breaks many apps
Takeaway: the opposite of Phantom: rules live on-chain, execution depends on off-chain routing and keepers. For Mzia, the Swap + Price APIs enable voice "convert to USDT".
