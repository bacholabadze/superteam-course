Problem & users

  • Problem: self-custody is hard: keys, token accounts, fees, scams.
  • Users: retail traders (memecoins, NFTs, DeFi) and dApps that need a wallet their users already have.
  • Why Solana: sub-cent fees and ~400 ms blocks make frequent swaps and transfers cheap and instant; SPL standards let one wallet support every token.
  • Competitors: Solflare, Backpack, Jupiter Mobile, MetaMask, embedded wallets (Privy, Dynamic).

How it works · risks · improvements

Standard programs on-chain, the value is off-chain

On-chain

  • No custom core program: composes public programs
  • Balances, token accounts, every signed instruction
Programs used
System 1111… SPL Token Tokenkeg… Token-2022 Tokenz… ATA ATokenGP… ComputeBudget… Jupiter v6 JUP6Lkb…
Swap tx pattern

v0 tx + 4 lookup tables → Jupiter RouteV2 → TransferChecked; separate fee payer = "gasless"

Off-chain

  • Key generation & encrypted storage (on device)
  • Transaction simulation & scam blocking
  • Own RPC, indexer, prices, history
  • Swap-quote API, bridges, on-ramps
  • SDKs: Phantom Connect, Wallet Standard

Risks → improvements

  • Drainers/phishing: users sign what they don't understand → plain-language previews
  • Centralised backend (RPC, indexer) is a single point of failure
  • Seed-phrase loss is still #1 → trusted, verified recipients
  • English-first, screen-first UX → native language & voice
Takeaway: any wallet can use the same programs, so the competition is UX and safety. Native-language, voice-first UX on top of existing wallets is the open gap (what Mzia fills).
